# a11y harness

Verification tooling for the accessibility pass on `index.html`. It measures the
rendered page in real Chrome: contrast ratios come from actual pixels behind the
glyphs, not from source colors.

Everything runs against the repository's own `index.html`; scratch pages,
screenshots and the Chrome profile stay in `.work/` (gitignored).

## Requirements

- Python 3 with Pillow (`pip install pillow`)
- Chrome or Chromium. The path is found automatically on the usual install
  locations, or set `A11Y_CHROME=/path/to/chrome`.

Optional:

- `A11Y_PAGE=/path/to/page.html` audits a page other than `<repo>/index.html`.
- `A11Y_NO_SANDBOX=1` adds `--no-sandbox`, needed where Chrome's sandbox is
  unavailable (containerised CI runners). A local run keeps the sandbox on.

## Continuous integration

`.github/workflows/a11y.yml` runs the same three commands on every push to
`master`, every pull request, and on demand, with `A11Y_NO_SANDBOX=1`. The gates
run in this order because a page that scrolls sideways also distorts every rect
the contrast probe would sample:

1. `widths.py ci` — WCAG 1.4.10 reflow, 320-1440px
2. `probe.py ci` — WCAG 1.4.3 contrast on rendered pixels plus structure
3. `check.py ci before` — the acceptance spec against the committed baseline

A failing run uploads `out/*.json` and the screenshots from `.work/` as
artifacts, so a red build can be diagnosed without re-running it.

## Usage

```bash
cd tools/a11y

# 1. measure a candidate and write out/report-<tag>.json + out/widths-<tag>.json
python probe.py <tag>
python widths.py <tag>

# 2. assert the acceptance specs against that report
python check.py <tag>            # absolute specs (S1-S6, structural)
python check.py <tag> <baseline> # + differential specs (S7) against a baseline
```

Example — verify the current page against the pre-pass baseline:

```bash
python probe.py current
python widths.py current
python check.py current before
```

Exit code is 0 only when every check passes.

## Scripts

| File | Role |
| --- | --- |
| `probe.py` | Renders the page at four viewports, screenshots it with all glyphs hidden, and measures WCAG 1.4.3 contrast per element from the real backdrop pixels. Also collects structural checks (landmarks, skip link, `aria-hidden` icons, `:focus-visible`, `prefers-reduced-motion`). |
| `widths.py` | WCAG 1.4.10 Reflow gate: 320-1440px in exact-width iframes, reporting horizontal overflow and the elements whose right edge escapes the viewport. |
| `check.py` | Acceptance spec over the JSON reports. `S1`/`S2` contrast, `S3`-`S6` structural, `S7` differential against a baseline report. |
| `common.py` | Shared paths, Chrome resolution and the `<base>` tag that lets scratch copies load the page's relative assets from the repo root. |

## Notes

- Chrome headless clamps its window to ~500px wide, so the narrow viewports are
  rendered inside exactly-sized iframes instead of real windows.
- The generated reports are gitignored and regenerated by the commands above,
  with one exception: `out/report-before.json` is the pre-pass baseline that
  `check.py` needs for the `S7` differential checks.
- `S7` allows exactly two things to move, and nothing else:
  - the nav element rects on mobile viewports: the mobile nav wraps to two rows,
    which is the fix for the baseline overflowing at 320-640px;
  - anything below the nav moving by the same delta the taller nav imposes in
    the flow (+52px at 390px), keeping its x, width and height intact. That
    delta is derived from the reports, and a rect that moves by any other
    amount is still reported.

  Contrast, colors and every other rect stay under the differential check.
